# Modem Satellite — ESP32-C3-MINI-V1

Перенос `modem pocket satelite/main` с ESP32-S3 на **ESP32-C3, 4 МБ flash**. Основан на предыдущем проекте S3. Модем принимает миссии QGC WPL 110 по фреймированному UART-протоколу и загружает их в полётник по MAVLink. Это отдельная прошивка модема: протокол TF03 и обработка дальномера сюда не входят.

## Подключение

Все RX/TX указаны со стороны ESP. Уровни UART — **3,3 В TTL**, общий GND.

| Назначение | GPIO ESP32-C3 | Подключить к |
|---|---:|---|
| UART1 RX модема | 6 | TX модема |
| UART1 TX модема | 7 | RX модема |
| UART0 RX MAVLink | 3 | TX полётника |
| UART0 TX MAVLink | 10 | RX полётника |
| Управление ключом | 4 | Вход управления транзисторной схемой |
| OLED SDA (опционально) | 0 | SDA OLED |
| OLED SCL (опционально) | 1 | SCL OLED |
| Земля | GND | GND всех устройств |

Оба UART — **115200 8N1**. GPIO2/8/9 не используются. USB CDC использует встроенный USB, не UART0. Подключение/отключение USB **не меняет распиновку и не отключает приём от модема**. Прошивка стартует от внешнего питания без ожидания USB.

OLED 72×40 SSD1306/SSD1315, адрес 0x3C. Если дисплея нет, запуск продолжается. Полное отключение: `ENABLE_OLED=0` в `firmware/modem_c3/src/Config.h`.

## Автоматическое включение питания

1. После старта ESP **GPIO4 = LOW (0)**. Сохранённая с прошлого запуска миссия не включает ключ.
2. UART1 принимает новое задание от модема. Проверяются CRC, формат и точки миссии; миссия сохраняется в LittleFS.
3. Только после успешного сохранения **GPIO4 = HIGH (1)**: включается питание полётника и подключённых через ключ устройств. Модему отправляется ACK `79 01 55 47`; при неверной миссии/ошибке сохранения — NACK `79 01 14 47`.
4. ESP ждёт новый корректный MAVLink heartbeat полётника после принятия задания, а не просто байты UART. Heartbeat наземной станции не подходит.
5. По heartbeat автоматически начинается загрузка миссии. Завершение подтверждается MAVLink MISSION_ACK от выбранного полётника.

Ожидание не блокирует приём UART и веб-интерфейс. Через 30 секунд без heartbeat показывается предупреждение, ожидание продолжается. Питание остаётся включённым при ошибке/остановке загрузки, потере связи, завершении миссии и отключении Wi-Fi. **Перезапуск ESP снова выключает GPIO4.** Новое задание во время активной загрузки отклоняется, чтобы не заменить миссию посередине передачи.

Ручное переключение GPIO4 из браузера убрано; старый `POST /api/switch` отвечает HTTP 409. Кнопка Start Upload может повторить передачу только после принятого в этом запуске задания и при свежей связи с полётником. Stop Upload отменяет передачу/ожидание, но не снимает питание.

**ESP и модем должны питаться независимо от управляемого ключа**, иначе задание не сможет поступить при выключенном GPIO4. GPIO выдаёт только управляющий сигнал 3,3 В. Для N-MOSFET с истоком на GND нужна внешняя подтяжка затвора к истоку, например 10 кОм, чтобы держать ключ выключенным до `setup()`. Индикация GPIO показывает заданный уровень, а не измеренное напряжение питания.

## Собственная Wi-Fi сеть

- SSID **modem_bridge**, пароль **00000000**.
- Адрес **http://192.168.0.4** — открывайте напрямую по IP, DNS не требуется.
- ESP сразу создаёт AP; DNS UDP53 выдаётся клиентам через DHCP. Мощность 8,5 dBm.
- Wi-Fi выключается через **5 минут после запуска ESP**, на странице есть обратный счётчик. Миссия, UART и питание работают дальше.
- Для новой сессии Wi-Fi нужен перезапуск ESP — учитывайте, что он также выключает питание через GPIO4.
- После обновления отключитесь от Wi-Fi и подключитесь заново, чтобы получить адрес из новой подсети 192.168.0.x. Внешние сети Robokit и другие профили больше не используются.

В браузере показаны этап задания, приём в этом запуске, GPIO4, длительность включения, связь/возраст heartbeat, SYSID/COMPID, прогресс загрузки, подтверждение/ошибка, статистика модема, клиенты AP, DNS, оставшееся время Wi-Fi и свободная память. API `/api/status`: `sequence`, `switch`, `mavlink`, `protocol`, `wifi`, `freeHeap`. При потере HTTP-связи состояние отмечается неизвестным.

## Сохранённое поведение S3

- Фрейм `79 01 SizeLE Payload CRC16LE 47`, payload до 65535 байт; Python-отправитель приложен. Для него установите `pyserial` и положите свой `.waypoints` рядом со скриптом; чужие миссии и координаты в комплект не включены.
- CRC считается по заголовку и payload: polynomial 0x1021, init 0xFFFF, без отражения и без финального XOR; `123456789` → 0x29B1. В старом проекте он назван IBM-SDLC, фактически параметры соответствуют CCITT-FALSE. Байтовый алгоритм не изменён.
- Приём, проверка и хранение миссии LittleFS. Загрузка MAVLink выполняется по последовательности включения питания выше. Сохранены просмотр миссии, echo и журналы.
- Веб-интерфейс встроен в прошивку и разворачивается в LittleFS, отдельная загрузка `data/` не требуется. Редактируемые HTML/CSS/JS в `data/`; сборка обновляет `src/WebAssets.h` автоматически.
- Журналы сокращены до 16 КБ суммарно для C3 без PSRAM. Удалена лишняя 64-КБ копия payload при разборе; пределы протокола и количества точек сохранены.

Для приёма миссий через USB вместо UART1 установите **явно** `PROTOCOL_OVER_USB=1` и пересоберите. При этом RX3/TX10 MAVLink остаются прежними, UART1 не используется, USB-диагностика не смешивается с протоколом. По умолчанию `PROTOCOL_OVER_USB=0`: Python-отправитель подключают через отдельный USB-UART к RX6/TX7, а не к USB ESP.

## Готовый образ и прошивка двойным щелчком

[Скачать последнюю прошивку и комплект](https://github.com/dimaystinov/esp32-modem-satellite/releases/latest).

- **Windows:** распаковать исходники/комплект и запустить `FLASH_WINDOWS.bat`. Скрипт скачает Arduino CLI, ядро и библиотеки, соберёт прошивку и предложит порт ESP.
- **macOS:** распаковать комплект, подключить ESP по USB и открыть `FLASH_MAC.command`. Если запуск запрещён, в Terminal из папки проекта: `chmod +x FLASH_MAC.command && ./FLASH_MAC.command`.
- Первый запуск требует интернета и может занять несколько минут. Python/Git для этих двух запускателей не нужны.
- **ESP Flasher:** выбрать `modem-c3-v1.0.0-full.bin`, чип ESP32-C3 и адрес записи **0x0**. Сборка не требуется. Подробности: [инструкция по прошивке](docs/FLASHING.md).

Готовый `.bin` — образ памяти, не запускаемая программа. Сборку и запись запускают `.bat` / `.command`. Новая запись полного образа стирает сохранённую миссию и настройки LittleFS.

## Сборка через командную строку на Mac / Windows

Нужны Arduino CLI, Python 3 и Git в PATH. Все команды из этой папки. На Mac используйте `python3`, на Windows — `py -3` вместо него.

```sh
python3 scripts/setup.py
python3 scripts/build.py
arduino-cli board list
python3 scripts/build.py --port /dev/cu.usbmodem101
```

На Windows последняя команда:

```powershell
py -3 scripts/build.py --port COM5
```

Подставьте фактический порт. Скрипт сначала собирает и только при успехе пишет flash. При ошибке подключения: удержать BOOT, кратко нажать RESET/EN, отпустить BOOT, заново проверить порт. Закройте Serial Monitor перед прошивкой.

Зависимости: ESP32 core **3.3.11**, ArduinoJson **6.21.5**, U8g2 **2.36.17**, MAVLink c_library_v2 commit `ce3aedef37c74c4c95111cf2a3f112a2dbd7e99e`. Библиотека MAVLink находится локально в `.deps/`, установка скриптом.

Arduino IDE: **ESP32C3 Dev Module**, USB CDC On Boot **Enabled**, Flash Mode **DIO**, Flash Size **4MB**, Partition Scheme **Default 4MB with spiffs**. Открывать `firmware/modem_c3/modem_c3.ino`. Для IDE дополнительно поместите подготовленную `.deps/MAVLink` в папку пользовательских Arduino libraries; сборочные скрипты используют её напрямую.

Собранные файлы: `build/c3/`. `modem_c3.ino.merged.bin` — единый образ для записи с **0x0**, только ESP32-C3 4 МБ.

## Проверки

`tests/core_test.cpp`: распиновка, LOW при старте, автомат ожидания миссии/нового heartbeat, отмена, ошибка, перезапуск, CRC-вектор и парсер миссии с payload 65535 байт. `tests/frame_test.cpp`: ACK только после принятия приложения, NACK для отказа и неверной CRC. Сборка на C3 проверяется Arduino CLI. Аппаратная проверка модема, полётника, OLED и транзистора выполняется отдельно; эта новая прошивка пока не загружалась на устройство.

## Автоматическая сборка на GitHub

GitHub Actions собирает C3 при push в main и проверяет парсер, приём кадров и интерфейс. Тег `v*` собирает и публикует релиз: полный образ, отдельные компоненты, ZIP с исходниками и запускателями, SHA256 и сведения о сборке. Сборка воспроизводится с указанными выше версиями зависимостей.
